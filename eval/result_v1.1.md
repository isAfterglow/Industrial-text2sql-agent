## 耗时观察

- 成功执行的普通查询大多集中在 3.4s 到 9.7s，主要耗时都在 `generate_sql`。
- 前半段单表题的执行本身都很快，`execute_sql` 基本在 4 ms 到 33 ms；瓶颈仍然是生成阶段。
- 两个最慢的失败题都来自两表复杂 Top-K：
  - ID 12 总耗时 23.80s
  - ID 11 在修复成功前也用了 17.67s
- 需要修复的题目总耗时基本翻倍：ID 2 为 9.68s，ID 11 为 17.67s，ID 14 为 10.90s，ID 16 为 11.45s，ID 21 为 7.57s。
- 聚合类执行本身耗时明显更高：
  - ID 17 `execute_sql` 为 323.96 ms
  - ID 19 `execute_sql` 为 422.76 ms
  - ID 20 `execute_sql` 为 900.63 ms
- 安全拒绝请求几乎都在 2-4 ms 内结束，说明“预生成拦截”路径已经有效。

## 结论

- 本轮复测确认：单表基础查询、样本编号查询、时序明细查询、字段归属修复和多数聚合查询已经比较稳定。
- 当前仍需优先处理的两个点没有变：
  1. “峰值背面温度最低”这一类峰值 Top-K 还缺少可靠模板或确定性改写。
  2. “查询某白名单表的全部数据”还没有转成明确的策略拒绝或正确的全字段只读查询。
