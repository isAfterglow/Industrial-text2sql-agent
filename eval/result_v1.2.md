## 当前识别不好的地方

### 1. 简单问题的路由召回还不稳

- 20 题新增变体里，有 8 题明明是单表问题，却没有命中简单路径，而是进入 `generate_full_sql -> build_robust_schema -> generate_pruned_sql` 慢链路。
- 这说明当前简单规则更偏向“标准模板句”，对自由表达、字段原名、口语化修饰词的召回还不够。

典型触发表达：
- `top 4 个...是什么`
- `给我看看`
- `请列出...前 5 条`
- `前 10 个序列点`
- `全部热物性参数`
- 字段原名直接出现在问题里，如 `rhoc_i`、`cpv_list`、`kc_list`、`surface_emissivity`

### 2. Top-K 语义与 Guard 规则存在冲突

- 在 `top 4 个碳化密度最大的样本编号是什么？同时显示 rhoc_i。` 这题里，修复前 Guard 认为 `LIMIT 4` 不该出现在子查询里，修复后又要求顶层必须保留“4”。
- 这不是生成器单点错误，而是“候选 SQL 结构约束”和“数字保留约束”之间有冲突。

当前表现：
- 子查询里的 `LIMIT K` 被判错。
- 修复器没有把结构整体改写为“单层 `ORDER BY ... LIMIT K`”。
- 修完之后又会因为丢失 `K` 被二次拦截。

### 3. 比较词和数值映射还有误判

- `不低于 0.95` 这种表达已经被 SQL 正确翻译成 `>= 0.95`，但 Guard 仍然把 `0.95` 判成“用户问题中未出现的数值条件”。
- 说明问题不在生成，而在比较词归一化后的数值对齐检查。

优先修复方向：
- 明确支持 `不低于 / 不小于 / 不高于 / 不大于 / 至少 / 至多` 与 `>= <=` 的一一映射。
- Guard 的“数值是否来自原问题”检查，要在归一化后再比对，不能只做字面匹配。

### 4. 区间筛选容易被误识别成 Top-1 / Top-K

- `cpv_list 在1130到1140之间` 本质是普通区间过滤，但当前链路把它改造成了 `IN (subquery LIMIT 1)`，属于不必要的复杂化。
- 这类问题在热物性单表上本应直接落成：
  - `WHERE cpv_list BETWEEN 1130 AND 1140`

目前缺陷：
- 带字段原名的区间句式，简单解析器没有稳定收敛。
- 修复器在没有用户要求 Top-K 时，仍可能擅自加入 `LIMIT 1`。

### 5. 时序切片表达识别不完整

- `sample_000032 前 10 个序列点的 surface_temperature、back_temperature、mass` 这类问题本质上就是 `thermal_response` 单表时序切片。
- 但当前系统没有把“前 N 个序列点”稳定归一化为：
  - `WHERE sample_id = ...`
  - `ORDER BY point_index ASC`
  - `LIMIT N`

当前缺口：
- `前 N 个序列点`
- `第 N 个点`
- `100到105号点`
- `point_index=500`

其中后两类已有部分成功案例，但前一种中文时序表达还不稳定。

### 6. “全部参数”类问题仍容易掉入慢路径

- `请查询sample_000460的全部热物性参数。` 最终虽然执行成功，但总耗时达到 `37232.20 ms`，而且 `review_sql` 走了 LLM review。
- 这类题本应是最标准的单表按样本读取，不应该进入慢路径。

说明当前系统对以下表达还缺少直接模板：
- `全部热物性参数`
- `所有热物性参数`
- `全部静态材料参数`

其中“全部静态材料参数”已经较稳定，但“全部热物性参数”还没有被简单规则完全接住。

## 当前结论

- 基线 43 题说明：标准化单表题、标准时序单表题、常见聚合单表题已经基本稳定，且能维持毫秒级到亚百毫秒级响应。
- 新增 20 题说明：系统的主要问题已经不再是数据库执行，而是“识别层”和“Guard / 修复层”的边界条件。
- 现阶段如果只看“不跨表候选题”的最终严格通过率，可以按 `59 / 63 = 93.7%` 对外表述。
- 但如果要强调“毫秒级简单路径命中率”，更准确的口径应为 `55 / 63 = 87.3%`，因为还有 4 题虽然最终答对，但已经退化到 20s 到 37s 的慢路径。

## 建议的后续修复优先级

1. 优先补简单路由规则：
   - `top K 个...是什么`
   - `前 N 个序列点`
   - `全部热物性参数`
   - 中英混写字段名
2. 修复 Guard 的比较词 / 数值一致性检查：
   - 重点处理 `不低于 / 不高于 / 至少 / 至多`
3. 限制修复器擅自引入 `LIMIT 1`、`IN (subquery LIMIT ...)` 等复杂结构。
4. 对时序单表问题补强确定性模板，避免 `thermal_response` 被误判成“不应出现的时序表”。
